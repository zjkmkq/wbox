# 真机验证与截图巡检

## 为什么必须自证

没有自证能力时，流程是这样的：

```
用户截图 → 我猜原因 → 改代码 → 让用户再截图 → 还是不对 → 再猜
```

一个颜色问题能烧掉一整天，而且**结论永远是"可能"**。

有自证能力时：

```
编译 → 装机 → 截图 → 和参照图逐像素比 → 定位到具体原因
```

30 秒出结论。

## 四个动作

### 1. 编译（看字节数，不看退出码）

```
python scripts/build_draft.py <wbox工程> --out <鸿蒙工程>
```

输出：`ok=True 代码 N / 资源 M / 页面 K`，以及 HAP 字节数。

**判据是 `BUILD SUCCESSFUL` + 字节数**。退出码非零通常是沙箱拦了 `wmic.exe`。

字节数还能当回归指标：改动后突然变大，说明有垃圾进包（比如框架残类）。

### 2. 装机 + 首屏截图

```
python scripts/verify_device.py --wait 20 --tag v1
```

- `--wait`：启动后等多久再截图（首次启动慢，20 秒起）
- `--tag`：截图文件名标签
- `--bundle`：包名（多版本共存时必传）
- `--no-install`：只重启截图，不重装

产物落在 `shots/dev_<tag>.jpeg`。

### 3. 逐页巡检

用 `uitest uiInput click x y` 点，每点一次截一张图。

**坐标怎么算**：设备是 2832×1280，但逻辑坐标可能是 810×366。换算：
```
x_dev = x_logic × 2832 / 810
y_dev = y_logic × 1280 / 366
```

点偏了就会点到隔壁按钮——所以第一张图先确认布局，再算坐标。

**巡检清单**（H5 游戏类）：
- 首屏/标题页
- 设置页（每个开关都能点）
- 关于页
- 进入游戏后的 HUD
- 商店/内购页
- 任一弹窗
- 返回路径

### 4. 浏览器探针对比（分水岭工具）

```
node scripts/browser_probe.js <url> webgl out1.png 810x366 1
node scripts/browser_probe.js <url> canvas out2.png 810x366 1
```

它用本机 Edge 跑同一份 H5，可选强制 canvas/webgl，可指定视口和 DPR 精确复现设备条件。

**它能回答的问题**：
- H5 本身坏了？还是 ArkWeb 把它跑坏了？
- WebGL 和 Canvas 两种渲染路径的差异在哪？
- 某个颜色/布局问题是不是设备特有的？

## 截图怎么判读（经验）

- **纯色画面**：可能是空画布透出 body 背景，不是"渲染失败"
- **有形状但颜色不对**：tint/混合模式问题
- **全白**：白色材质没有被上色（tint 丢失）
- **文字被截断**：布局宽度问题（工作台自己也会有这个问题，见下）
- **画面正确但点不动**：触摸被遮罩吞了

## 逐像素对比怎么做

```python
from PIL import Image, ImageChops
a = Image.open("webgl.png").convert("RGB")
b = Image.open("canvas.png").convert("RGB")
diff = ImageChops.difference(a, b)
# 统计差异 > 40 的像素占比
```

局部对比比整屏对比更能说明问题（标题区、按钮区单独算）。

跳石子工程验收数据：整屏 0.77%，标题区 0.26%，按钮区 0.05%。

## 工作台自己的 UI 也要验证

工具也会有文字遮挡问题。工作台内置 `scripts/check_text_clip.py`，用 `fontMetrics().boundingRect()` 对比每个可见 QLabel 的实际宽度，输出可能被截断的控件。

改完界面跑一遍，输出必须为空。

## 一个反例（记下来别再犯）

早期我让用户帮忙截图，然后把"看起来像"当成"是"。结果：
- 把"空画布透出的深蓝底"判成"渲染失败"
- 把"夜间主题的浅色字+浅色描边"判成"字体缺失"
- 把"程序生成素材慢"判成"卡死"

**每个判断都要有一个可复现的验证动作**，没有就标注为"待验证"，不要说成结论。

# 工作台设计与扩展指南

## 设计原则

### 1. 迁移不是翻译，是参照重做

原应用拆成三类**参考**：资源、逻辑、行为。鸿蒙侧重新做，中间"没做到位"的地方显式记录成缝。

所以工作台不提供"一键翻译 Java → ArkTS"，它提供的是**判断链**：每条资源/模块都要有人做决定，并且留下理由。

### 2. 唯一数据契约

`spec.json` 是唯一纽带，读写只能走 `src/wbox/spec.py`，禁止各模块自己 `json.load`。

它有严格的 schema（`additionalProperties: false`），版本化（`spec_version`），保存是原子写（临时文件 + `os.replace`）。

**为什么这么严**：迁移过程会产生大量中间判断，如果每个模块自己读自己写，改一次结构就全崩。

### 3. 人保留判断权

`decided_by` 恒为 `human`。AI 只提案。

### 4. 验证内置

编译/装机/截图/巡检/对比全部是工具能力，不是文档里的命令行。

## 目录结构

```
src/wbox/
  spec.py          数据契约（唯一入口）
  extract.py       拆包 → 清单/模块/行为
  plan.py          提案生成
  taskpack.py      任务包导出
  draft.py         草案解析与落盘
  assemble.py      装配（draft + 资源 + 骨架 → 工程）
  hvigor.py        编译
  deps.py          依赖检测与安装
  ascii_names.py   中文路径 → 拼音
  shapes/          形态模板（JSON，数据驱动）
  tutorials/       教程（Markdown，数据驱动）
  templates/harmony/   鸿蒙工程骨架（17 文件）
  gui/             界面（PySide6）
```

**关键设计**：`shapes/` 和 `tutorials/` 是**纯数据**。加一个新形态或一篇新教程，不需要改代码。

## 怎么加一个新形态

1. 在 `src/wbox/shapes/` 新建 `xxx.json`
2. 必填字段：

```json
{
  "shape_id": "唯一 ID",
  "name": "人类可读名",
  "summary": "一句话说清这是什么",
  "effort": "成本量级",
  "detect": {
    "any": [{"path_glob": "..."}],
    "contains": [{"path_glob": "...", "pattern": "正则/字面量"}],
    "exclude": [{"path_glob": "..."}]
  },
  "migrate": {
    "approach": "策略名",
    "steps": ["有序步骤"],
    "resource_strategy": {"mode": "tree|map|semantic-map|none|extract-only", "note": "..."},
    "bridge": [{"need":"","reason":"","how":""}],
    "renderer_profile": {"rule":"","why":"","fallback":""},
    "pitfalls": [{"symptom":"","cause":"","fix":""}],
    "verify": ["验收项"]
  },
  "cases": [{"name":"","note":""}],
  "tags": []
}
```

3. 重启工作台，形态诊断会自动加载它
4. 拿一个真实 APK 验证 `detect` 能命中（**没验证过的模板等于没有**）

## 怎么加一篇教程

1. `src/wbox/tutorials/` 新建 `xx-标题.md`
2. 头部 front-matter：

```markdown
---
title: 标题
summary: 一句话摘要（列表里显示这个）
tags: [标签1, 标签2]
steps: [extract, assemble]      # 关联到哪几步，右栏按当前步骤推荐
order: 12                        # 排序
---
```

3. 正文用标准 Markdown。**表格谨慎用**（Qt 的 markdown 渲染对表格支持有限），优先用列表和代码块。

## 怎么加一个新步骤

1. 在 `gui/steps/` 新建页面类，继承现有步骤基类
2. 在 `gui/steps/pages.py` 注册（`STEPS` 列表，按顺序）
3. 步骤要能读写 spec，不要自己存私有状态
4. 在 `check_text_clip.py` 里确认新页面没有文字截断

## 怎么加一个新面板

- 左栏：`gui/panels/inventory.py` 的模式（跟 spec 同步刷新）
- 右栏：现在有两个 Tab（帮助中心 / 记录），新面板加 Tab 而不是挤位置
- **注意**：任何长文本控件必须 `setWordWrap(True)` + `setMinimumWidth`，表格必须 `setWordWrap(True)` + `resizeRowsToContents()`。这是工作台反复出现的"文字被遮挡"根因。

## 扩展流程：从"丢安装包"到"出安装包"

目标形态是一键流水线，它的前提是**模板覆盖足够多的形态**。扩展路径：

1. 遇到新形态 → 走专家模式迁移一遍
2. 迁移过程中的每个判断记录进 spec
3. 把判断抽象成模板（`shapes/xxx.json`）
4. 用第二个同类 APK 验证模板的 `detect` 和 `steps` 是否真的可复用
5. 可复用了 → 一键流水线就能吃这一类

**不要为单个案例编模板**。模板的价值是"第二个同类包能直接用"，只有一个案例时它只是笔记。

## 测试与自检

```
# 离屏冒烟（必须全绿）
env -u CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR -u CODEBUDDY_TOOL_CALL_ID QT_QPA_PLATFORM=offscreen \
  python scripts/smoke_gui.py

# 文字截断自检
python scripts/check_text_clip.py

# 路径 ASCII 自检
python scripts/check_ascii_paths.py
```

改完 UI 三者都要跑。

## 打包

```
pyinstaller --noconfirm wbox.spec
```

注意：`shapes/` 和 `tutorials/` 是数据文件，**必须加进 spec 的 datas**，否则打包后界面能开但模板和教程是空的。

# 形态诊断

## 为什么先诊断

五种形态的成本差一个数量级：

- Cordova/H5 壳：**1~2 小时**
- 远程 WebView 壳：**半天**（但要先做产品判断）
- 常规原生：**每页 0.5~1 天**
- libGDX 原生游戏：**3~5 天**（重做玩法）
- Unity：**不建议承接**

先花 5 分钟诊断，可以省下三天。

## 判定指纹（看这几个文件就够了）

### 1. Cordova / Capacitor 壳 + H5
```
assets/public/index.html        ← 最硬的证据
assets/www/index.html
bundle 里出现 "Capacitor" / "cordova"
```
再补一刀确认引擎：
```
grep -o "Phaser v" assets/*.js        → Phaser
grep -o "CocosEngine\|cc\.game"       → Cocos
```
**成本**：低。原生侧只要 3 个文件（容器页 + 桥接 + 入口 Ability）。

### 2. 远程 WebView 壳
```
smali 里 loadUrl("http...")，且 assets 下没有本地 html
```
**成本**：极低，但要先回答：这个远程站点还会不会挂？挂了迁过去就是白屏。

### 3. libGDX 原生
```
lib/arm64-v8a/libgdx.so
assets/ 下有 .atlas / .fnt
```
**成本**：高。要重做玩法，不是翻译代码。

### 4. Unity
```
lib/**/libunity.so
assets/bin/Data/globalgamemanagers
```
**成本**：不承接（除非拿到 Unity 工程源）。

### 5. 常规原生
```
res/layout/*.xml + smali 里 setContentView / extends Activity
```
**成本**：中。

## 一个反直觉的判据：别用包名和体积

- 包名可以随便改
- 体积不能说明任何问题（H5 游戏的 assets 可能是空的，美术 100% 代码生成）
- 文件后缀也不可靠（`.js` 可能是库）

**只看结构指纹和引擎常量字符串。**

跳石子工程的美术是 100% 程序化生成的（`createCanvas` 21 处、`fillRect` 97 处），原 APK 的 `public/` 里**一张图都没有**。第一次见到时以为是素材丢失，白找了一轮。

## 诊断报告怎么读

- **命中形态**：可能多个（H5 壳 + Phaser 引擎特征同时命中），按证据强度排序
- **证据**：命中了哪条规则、在哪个文件里找到的
- **迁移步骤**：模板给的有序步骤
- **已知坑**：这一形态踩过的坑，带症状/原因/解法
- **验收清单**：做完怎么算做完
- **预计工作量**：模板给的量级，不是精确估算

## 判完怎么走

- 命中且有把握 → 一键流水线
- 命中但想控制细节 → 五步专家模式
- 未命中 → 走专家模式，顺手把新形态补成模板（下次就有了）

# AI 协作迁移指南

## 分工的底线

**AI 提案，人决定。**

契约里 `decided_by` 永远是 `human`。这不是形式主义——迁移里有一类判断是 AI 做不了的：

- 这个资源删了会不会有玩家投诉
- 这个动画的手感对不对
- 这个游戏是不是破解版、要不要保留破解行为
- 这个成本值不值得

AI 擅长的是：提炼数值、生成样板代码、把已知坑套到新案例上、写验证脚本。

## 任务包怎么写

导出的 `ai_output.md` 里包含：

1. **形态结论**（你判的，不是 AI 猜的）
2. **资源清单**（哪些要迁、哪些弃）
3. **行为骨架**（入口、关键类、核心数值）
4. **目标**（要生成哪些文件、放哪、什么格式）
5. **约束**（用什么 API、不能用什么）

**约束那部分最关键**。不写清楚，AI 会给你一份"看起来对但跑不起来"的代码，比如：
- 用 `CanvasRenderingContext2D.drawImage`（鸿蒙没有）
- 用 `setWindowOrientation`（不存在，正确的是 `setPreferredOrientation`）
- 用 `module.json5` 的 `routerMap`（FA 老字段，会白屏）

## 交付物格式

AI 要返回**可粘贴的 FILE 块**：

```
// FILE: entry/src/main/ets/pages/Index.ets
import { webview } from '@kit.ArkWeb';
...
```

首行 `// FILE: 路径` 是元数据，导入时会被消费。

**HAP 不是这一步的产物**。想要 HAP 得走装配和编译。

## 常见失效模式（以及怎么防）

### 失效 1：AI 不知道形态
它会按"常规 Android 应用"给你生成一堆页面，而这个包其实是 H5 壳。

**防法**：在任务包第一段就写死形态结论和证据。

### 失效 2：AI 不知道设备限制
它会用 WebGL 思路写渲染代码，但模拟器没有 WebGL。

**防法**：把设备的真实能力写进约束（"webgl2/webgl 均为 null，只能 Canvas"）。

### 失效 3：AI 编造 API
它会给不存在的鸿蒙 API。

**防法**：要求它"只使用我给的 API 清单里的方法"，超出就报错而不是猜。

### 失效 4：AI 把框架噪音当业务
134 个 Capacitor 类会被它当成要迁的模块。

**防法**：任务包里明确列出"这些是噪音，不要出现在代码里"。

## 一轮对话 vs 多轮

**首轮就要给全上下文**。分多轮补充会让它反复推翻前面的结论。

如果首轮产出不合格，不要在原对话里"再改改"——把不合格点写成明确的反例，重新给一次完整任务包。

## 验收 AI 产出的三条

1. **能编译**（不是"看起来对"）
2. **数值对得上**（提炼出来的数字必须一致）
3. **没有凭空造 API**（逐个对照清单）

## 一句话总结

**AI 是副驾驶，不是自动驾驶。** 你负责"这是不是对的"，它负责"把它写出来"。

工作台把这条原则写进了数据契约（`decided_by: human`），不是靠自觉。

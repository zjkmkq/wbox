# 一键流水线

## 它是怎么工作的

```
选中 APK
  ↓
判形态（代码级指纹，不猜）
  ↓
命中模板？──── 否 ──→ 停下，告诉你「这是新形态」+ 已有模板清单，建议走诊断/专家模式
  │ 是
  ↓
按模板的资源策略搬迁资源
  ↓
按模板的最小页面骨架生成 ArkTS（容器页 / 桥接 / 入口 Ability）
  ↓
注入模板要求的兼容层（如 tint bake、振动桥）
  ↓
装配 → 编译 → 出 HAP
  ↓
装机（可选）→ 启动 → 截图 → 出报告
```

## 它会拒绝你的三种情况（这是特性，不是 bug）

1. **形态是 Unity** —— 模板明确写"不可白盒迁移"。它会直接告诉你结论，而不是假装能跑。
2. **形态没命中任何模板** —— 它列出候选证据，让你判断是不是新形态。
3. **命中了模板但必需依赖缺失** —— 比如没有 SDK，它会停在"环境不完整"，并给出去设置装插件的位置。

**一个永远说"成功"的工具是没有价值的。** 它必须能说"这个包做不了"。

## 什么时候该用它

- 同一个形态你已经走过一遍，模板已固化
- 你要的是"能不能出包"，不是"每个资源的去留"
- 批量处理多个同形态的包

## 什么时候不该用它

- 第一次遇见这个形态（模板还在建立中）
- 你需要精确控制资源取舍（走专家模式）
- 包里有破解/篡改痕迹需要保留或还原（这类判断必须人来做，见下）

## 关于"改过的包"

同一个游戏可能存在多个版本（原版 / 破解版 / 去广告版）。一键流水线**不会替你判断该保留哪个版本的行为**，它只按原样迁移。

如果需要出"正常版"，应该是：
1. 先用流水线出原样版本
2. 再基于它派生出修复版（改包名、改关键逻辑）
3. 两版并存，分别验证

跳石子工程就是这么做出来的：破解版（`com.webdevbrian.skipthestone`）+ 正常版（`...skipthestone.normal`），两份 HAP 可在同一台设备共存。

> 注意：派生版工程**不能再被流水线覆盖**。流水线会按原始资源重新装配，把派生版的修改刷回去。

## 失败时你看到什么

- 停在第几步
- 那一步的具体原因（文件级，不是"出错了"）
- 已经产出的中间物在哪（可继续用专家模式接手）
- 建议的下一步

流水线的价值不在"全自动"，在"失败时留下可继续的现场"。
